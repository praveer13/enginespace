# Upstream state: SGLang, Mini-SGLang, attention backends, tools, rental prices, datasets

Research key `sglang`. Checked 2026-11-03 (the fetches ran 20:05-20:45 PST, which is 2026-11-04 04:05-04:45 UTC). Written for enginespace, the Engine Internals specialization. It tests the claims in `kernelspace/SPECIALIZATIONS.md` §3.5 and §10 and says what each result changes in TR0-TR8 and the capstone.

**Conventions.**
- **[measured]**: I read or counted it myself from the primary source on 2026-11-03. That covers a version string, a date, a price on a page, a line count, or a default in source.
- **[derived]**: arithmetic on measured inputs, or behaviour I inferred by reading source or docs. I did not run any engine or GPU code.
- **[estimated]**: my judgment.
- **[unverified]**: an upstream project reports it and I did not reproduce it, or I could not check it. Every upstream performance figure is [unverified].
- **"vs catalog"** is one of: confirms, changes, new (the catalog is silent), cannot verify. In the structured result, confirms and new map to `verified`, changes maps to `changed`, and cannot verify and vendor-reported figures map to `unverified`.
- **TTL** is the re-check interval. Prices follow PLAN-100X's 90 days. A row's fact date is when upstream published, merged or released it.
- Raw pulls are untrusted data kept outside the repo. Each row names its URL, so a reader can re-fetch.

### TR1. Read the engines
- **Pin Mini-SGLang to `9a91cfa` (M1).** It has no tags and has been quiet for 170 days, so it will not move under the course. ### TR2. The step loop
- Mechanism and switches: SGLang overlap on by default, `--disable-overlap-schedule` (O1); Mini-SGLang `MINISGL_DISABLE_OVERLAP_SCHEDULING=1` (M3); TRT-LLM overlap on by default at the cost of one extra decode step (G6); vLLM `async_scheduling` is a tri-state that is `None` by default (`config/scheduler.py` at v0.33.0), and PR #27614 made it default-on (W2). A four-engine ablation table is cheap to build.
- Sim fidelity points that real SGLang makes visible: the one-batch result lag (O1), the opt-in consecutive-prefill exception, and delayed sampling for grammar (O4). W2 gives the TTFT cost to reproduce: TPOT falls, TTFT rises slightly.
- CUDA-graph modes and keys: SGLang {full, breakable} per phase (G1) with bucket lists (G2); vLLM's five modes, with the dispatch key depending on the runner (G4). The bucket lists differ: SGLang decode `[1, 2, 4, 8, 12]`, then steps of 8, 16 and 32; vLLM `[1, 2, 4]`, then steps of 8 and 16 (`upstream-vllm.md` G2). A sim that pads a batch up to the next captured size reproduces both. Mini-SGLang's `GraphRunner` is the minimal version: static `input_ids`, `out_loc`, `positions`, `logits` buffers, `pad_batch`, `replay`.
- The 4090 cliff (G3): above 48 concurrent decodes SGLang should fall back to eager on a 24 GB card [derived, not run]. Predict first, then measure at concurrency 32, 48, 49, 64. This costs well under an hour of a $0.34-0.89/h GPU [estimated].
- The sim's dials can match SGLang's real ones: `schedule_policy`, `max_prefill_tokens`, `chunked_prefill_size`, `num_continuous_decode_steps` (default 1) (O5).
- Reference format for per-step output: the Simulator's `iteration.jsonl` (batch composition and predicted latency) (T9). Exporting the same fields from the Trace Room sim would let a learner diff the two.
- Cite W1 (+56.2% for a tiny model on a fast GPU) as the motivating number, not as a target. O2's 2024 figures are history.

### TR3. Profile a real engine
- Procedure for SGLang: set `SGLANG_TORCH_PROFILER_DIR`, `POST /start_profile` with `num_steps` and `start_step` (skip warmup), optionally `detailed_annotations` and `profile_by_stage`, open the `*.trace.json.gz` in Perfetto (T1, T2, N3). `python -m sglang.profiler` also writes `server_args.json`, which is ready-made provenance for a pinned trace.
- The `step[...]` labels (T2) are machine-readable ground truth for "find the gap, name the sync" span checks, and they carry the sums a roofline needs.
- nsys: use `--cuda-graph-trace=node` to see kernels inside graphs (T3). NVTX and Python-source attribution need graphs off, so the lab needs a graph-on and a graph-off run. nsys 2026.5.1 adds `--pytorch=functions-trace` for CPU-side attribution (N1).
- Provider pre-flight, as the first lab step, four lines: `nvidia-smi` driver >= 580 (R5); `cat /proc/sys/kernel/perf_event_paranoid` (N4); the GPU name (Modal: `gpu="H100!"`, C4); and an ncu probe (N5): `ncu --launch-count 1 python -c "import torch; a=torch.randn(4096,4096,device='cuda'); (a@a).sum().item()"` and look for `ERR_NVGPUCTRPERM`. I have not run it. A 15-minute 4090 probe costs about $0.09-0.22 [derived]. Record the result in the evidence file; never gate credit on it.
- Keep pinned traces under about 100 MB (N3). For larger ones, Perfetto's `trace_processor server http` accelerator is the documented route.
- Citable write-ups: W1, W2, W4, W5, W6. Treat W7 as a hypothesis to measure.
- `llm-torch-profiler-analysis` (Z3) is a reference for the categories and for "hidden vs exposed". The local grader's consistency checks can use the same definitions: kernel time on a stream, exposed time, gaps between consecutive kernels.

### TR4. Backends as a consumer
- One matrix, hardware x engine default (A3, A4): 4090 (SM89): vLLM FA2, SGLang `flashinfer`; H100 (SM90): vLLM FA3, SGLang `fa3`; B200 (SM100): vLLM FA4, SGLang `trtllm_mha`. FA3 exists only on Hopper; FA4's README says Hopper and Blackwell (A3).
- A 4090 learner can sweep FA2 and FlashInfer (FA4 on SM8x is unverified, A3). FA3 sweeps need an H100 ($1.99-3.99/h, C1); Blackwell sweeps a B200 ($5.98-7.99/h).
- FlashMLA (A5, A6): upstream HEAD no longer builds for Hopper, but both engines ship Hopper-capable forks. Reading targets for an H100 learner are `sgl-project/FlashMLA` `csrc_legacy/` and `vllm-project/FlashMLA` at `e2afa5f`, not `deepseek-ai/FlashMLA` `main`. The 60-day TTL fits: the drop landed 24 days before the catalog, and SGLang's fork wheel appeared 22 days after it [derived].
- Pin exact versions: FlashInfer 0.7.2.x (A1), flash-attn-4 to one beta number (A3; weekly betas make "latest" meaningless), FA2 v2.8.3.post2, FlashMLA by fork.
- SGLang's 25 backend names (A4) include deprecated aliases (`nsa`, `compressed`, `tokenspeed_mla`) and new ones (`hpc_ops`, Tencent, Hopper only, page size 64). Predict-then-reveal reads should use the auto-selection table, not the full list.
- TRT-LLM is now a PyTorch engine (A7) and vendors a FlashInfer CuTe DSL kernel, which makes it a fourth consumer to mention.

### TR5a. Hybrid KV groups and adapter pages
- SGLang's answer key for hybrid groups is `UnifiedRadixCache` (X5): FULL, SWA, MAMBA components over one tree; the reusable boundary is the deepest node where every validator accepts; SWA leaves tombstones; sidecars follow a source pool. These map directly onto `hybrid-kv` property tests: (1) a boundary is reusable only if all components accept; (2) tombstoned SWA slots do not break ancestors; (3) evicting one component does not delete a node another component anchors.
- Pool layout: opt-in `--enable-unified-memory` makes one byte buffer split dynamically between sub-pools (X5). Compare with the static default.
- **Adapter pages (X6):** SGLang's LoRA pool is slot-based, not a shared page pool. The module should present "adapter pages in the KV pool" as the S-LoRA paper's design that the learner implements, and say plainly that upstream SGLang does not do it. Reading target: `lora/mem_pool.py` (`get_available_buffer_slot`, eviction). vLLM's pool is the `vllm` key's to check.
- The Rust core (X2) supports exactly these component sets, which makes `unified_tree_core.rs` and its `src/tests/components/*.rs` readable test oracles for a Rust-first learner.
- Eviction policy knobs (lru, lfu, slru, priority, tlru) are the TR5a/TR8 bridge: a policy changes hit rate, and hit rate changes TTFT.

### TR5b. Native offload; connector contract; event publisher
- HiCache's tier model (H1) is "native offload". The `HiCacheStorage` ABC and the `file` backend (documented as "for demonstration purposes") are the model for a toy connector (F lane). Mooncake, 3FS (`hf3fs`), NIXL and AIBrix are the production L3 backends.
- Event publisher (H2): conformance can be graded on the schema (`BlockStored` / `BlockRemoved` / `AllBlocksCleared`, `KVEventBatch` with `ts`, `events`, `attn_dp_rank`) and on ZMQ behaviour (`buffer_steps` 10,000, `hwm`, replay endpoint). The adapter fields (`lora_id`, `lora_name`) mean the contract WR3 specifies must carry an adapter dimension.
- External router integration: Mooncake object-key layout is exposed at `GET /get_hicache_l3_cache_layout` and in `/server_info` (HiCache design doc). That is a concrete "engine side" of a router contract.
- A real consumer with documented gaps (H3): `sgl-kv-indexer` ignores publisher sequence gaps, re-applies redelivered batches in arrival order, and has no replay or restart recovery. A conformance suite for the publisher should test exactly those: a dropped batch plus `replay_endpoint` refetch, a duplicated batch, a reordered batch, a reconnect, and a worker restart. The grade is on the publisher's behaviour, not the indexer's.
- LMSYS's 2026-11-02 HiCache post (CP, PP, speculation, P/D) reports a production case, hit rate from about 30% to 95% and median TTFT under 3 s on GLM-5.1/5.2 coding workloads [unverified, vendor-reported]. Use it as a reading item, not a target.
- PD transfer backends: `mooncake`, `nixl`, `ascend`, `fake`, `mori`, `mooncake_tcp` (`choices.py`). `fake` is useful for a no-network test of the engine side.

### TR6. Speculation and structure
- Rejection sampler and EAGLE-3 (P1): SGLang's flags map to the lab's two verifiers, token-wise (`--speculative-use-rejection-sampling`) and block verification (`--speculative-use-block-verification`). Implement both and test exactness with the chi-square lab.

- MTP runs through the EAGLE workers (P1). Draft cost sits in TR6; SH5 covers batch 1 on devices.
- Grammar mask overlap (O4): the answer key is the grammar barrier inside `verify()` for EAGLE, STANDALONE and DFlash, delayed sampling for the non-speculative path, and a synchronous fallback for NGRAM. The timeline lab can draw all three on one axis.
- Structured-output backends (P4): xgrammar default, with the engine's pins as the reference. T6.L8's XGrammar is current.
- Docs numbers (P2) are sanity checks only.
- Feasibility on a 4090: not checked. A 24 GB card running an 8B target plus an EAGLE-3 draft was not verified; budget a test before committing a lab to it.

### TR7. Contribute honestly

### TR8. Benchmark like you mean it
- The tools' defaults are teaching material. Seeded real examples for the broken-benchmark corpus, each from source (T5, T7, D3):
  1. Closed loop in disguise: `--max-concurrency` with a rate, where the help text admits the rate "may be lower".
  2. Client-queue blindness: SGLang's timer starts after the semaphore. vLLM exposes `client_queue_time` and `e2el_including_client_queue` for the same case.
  3. Warm-cache leakage: warmup repeats request 0 and the flush is off by default.
  4. EOS ignored by default (`ignore_eos` true), which distorts speculation and structured output.
  5. The client as bottleneck (T8): 2,500 requests, 106.8 s vs 13.2 s on the same mock server.
  6. Length-shaped, not time-shaped, BurstGPT replay (D3).
  7. Hardware label drift: Modal's `H100` may be an H200 (C4).
  8. An uninstrumented residual called "CPU time" (X4).
  9. Cost blindness: Modal bills CPU and memory on top of the GPU (C3).
- Open loop done right: SGLang `--request-rate` with a seed (default 42) is Poisson (T5); vLLM adds Gamma `--burstiness` (T7). Goodput at SLO now has an upstream definition (T6): requests that met every SLO, divided by total run time. The `knee` exercise divides by the fixed arrival window, so TR8 must name its denominator.
- Confidence intervals: I found no bootstrap CI option in either tool's docs [derived]. The course supplies bootstrap code, and steady-state trimming exists upstream (`steady_state_serving`, T6).
- BurstGPT replay (D1-D3): build a converter that branches on the header, writes length and timestamp pairs, and drives either a course-owned open-loop replayer or the Simulator's Autobench JSONL (T9). The Simulator gives a free, no-GPU twin of the replay. Pin each CSV by sha256 and credit the paper.
- ShareGPT (D4): download at run time, never ship.
- Costs: the catalog's $24-54 holds (C2). A full BurstGPT busiest-hour replay on one H100 PCIe is a few dollars [estimated].

- Candidate commit pairs must be built against a pin. For SGLang use v0.5.23 or later; for FlashMLA-involving pairs, say which fork.
- Any pair that touches CUDA graphs needs the 4090 or H100 memory-bracket defaults (G3) in the writeup, since the defaults change by GPU.
